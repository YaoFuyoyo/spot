# 产品分类知识库 · 产品词补充

## 用途

把「企业高频使用的产品词」补进产品分类知识库，输出可直接落表到【结构化】sheet 的数据行，
并保证编码、层级、行业大类、同义词格式符合《产品分类知识库维护手册》。

## 输入 / 输出契约

- **输入**：`产品补充：【产品词】`（可附 `--kb` 指定其他数据源；缺省连接平台 SQLite 知识库 `data/addprod.sqlite`，与 tool-addprod 平台同源、随存档实时更新）
- **输出**：【结构化】sheet 需要的数据行，字段固定为
  `产品编号 + 产品名称 + 产品层级 + 产品行业大类 + 产品同义词`
  以表格 + TSV 两种形式给出（TSV 便于直贴 Excel）。

## 输出条数规则（硬性）

| 情形 | 需返回条数 | 说明 |
|---|---|---|
| 作为老词同义词 | 1 条 | 返回被挂接节点的整行（同义词字段已含新词） |
| 新增 4 级产品 | 1 条 | — |
| 新增 3 级产品 | ≥ 2 条 | 该 3 级 + 其下一个 4 级 |
| 新增 2 级产品 | ≥ 3 条 | 该 2 级 + 其下一个 3 级 + 该 3 级下一个 4 级 |
| 新增 1 级产品 | ≥ 4 条 | 逐级向下各补一个，直至 4 级 |

即：**新增且不是 4 级时，必须把其下各子级每个层级至少补一个产品，形成完整的 4 级链路。**
补齐的下级产品必须是真实存在的产品词（优先复用知识库中同类分支已有名称，或取自《统计用产品分类目录》等手册列出的权威目录），
**不得凭空编造**；如无可靠依据，明确说明并请用户确认，而不是随便填一个。
**无法可靠补齐下级时，优先改选不需要新增下级的挂靠方案**（如把细分词挂到既有「其他XX」3 级之下作 4 级），
而不是返回无法确认。

所有路径均**相对技能根目录**，脚本用 `__file__` 反推根目录，因此从任意工作目录调用都有效。

| 资源 | 相对路径 |
|---|---|

| 知识库（xlsx 快照） | `references/产品分类知识库.xlsx`（离线场景 / 导出模板，不随平台更新） |
| 维护手册 | `references/产品分类知识库维护手册.docx` |
| 规则摘要 | `references/维护规则.md` |
| 结构说明 | `references/知识库结构.md` |
| 查询脚本 | `scripts/query_kb.py` |
| 落表脚本 | `scripts/apply_kb.py` |
| 公共层 | `scripts/kb_common.py`（依赖检查、数据源解析、打开校验、写入预检；两个脚本共用，勿单独删） |

## 运行环境（首次执行前确认）

- **Python 3.8+** 与 **openpyxl**。缺依赖时脚本会自行报错退出（退出码 2），不会抛裸堆栈。
  安装（建议隔离环境，不要污染全局）：
  ```bash
  <python> -m venv <venv> && <venv>/Scripts/pip install openpyxl
  ```
- 命令中的 `python` 泛指当前环境可用的解释器；若环境里没有 `python` 可执行文件，用实际解释器绝对路径调用脚本。
- **中文编码**：脚本已强制 UTF-8 输出。但通过命令行传中文参数（如 `--add "...|盾构机|..."`）仍可能受宿主控制台编码影响；
  **涉及中文的新增，一律优先用 `--spec spec.json`（UTF-8 文件）**，命令行简写只用于纯 ASCII 场景。

## 退出码约定（供自动化调用判断）

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 用法或 IO 错误（如知识库路径不存在） |
| 2 | 缺少依赖 openpyxl |
| 3 | 结构不符（sheet 名或表头与预期不一致） |
| 4 | 写入预检未通过（知识库含公式/图表/图片/透视表，openpyxl 保存会损坏） |

结构不符时可用 `--sheet-struct` / `--sheet-level` 指定实际 sheet 名，或 `--ignore-header` 跳过表头校验。
预检拦截时确认可承受再加 `--force`。

## 工作流

### 步骤 1 · 加载规则与知识库
- 读取 `references/维护规则.md`（编码规则、格式规范、修正原则）与 `references/知识库结构.md`（sheet 结构、既有惯例）；
  规则细节以 `references/产品分类知识库维护手册.docx` 原文为准。
- 用 `scripts/query_kb.py` 查询，不要手写解析代码（缺省连平台 SQLite，与 tool-addprod 平台同源；xlsx 快照用 `--kb references/产品分类知识库.xlsx`）：
  ```bash
  python scripts/query_kb.py info                       # 知识库快照：行数/排序/一级节点数（先跑它自检）
  python scripts/query_kb.py check  <产品词>          # 存在性 / 冲突 / 噪声预检
  python scripts/query_kb.py find   <关键词> --replace # 按统一替换词展开后检索
  python scripts/query_kb.py path   <产品编号>         # 打印 1→4 级归属链
  python scripts/query_kb.py children <产品编号>        # 列出直接子级
  python scripts/query_kb.py next   <父级编号>         # 计算下一个可用同级编码
  python scripts/query_kb.py l1                        # 列出全部一级节点（定行业大类用）
  ```

### 步骤 2 · 存在性校验（能否直接命中）
依次检查，任一命中即为「老词」：
1. 精确产品名相同；
2. 已作为某节点的同义词存在；
3. 按**统一替换词规则**展开后等价（如 机械/机器/设备/装备/装置/仪器/器材/器具/器械 互通）。

### 步骤 3 · 层级关系判断（决定新增还是同义词，本步最关键）
即使步骤 2 全部未命中，仍须对每个候选归属节点判断**该词与节点的层级关系**（上位统称 / 下位细分 / 同层并列）：

- **上位统称** —— 该节点下已有多个平级细分，该词是它们共同的统称（如「工程机械」之于桩工机械/混凝土机械…）
  → **只能作为该节点的同义词**，禁止新增。
  （依据：唯一性原则 + 完整性原则「不新增层级」；先例 `3515 农业种植机械` 挂统称词「农业机械」。）
- **下位细分** —— 该词比节点更具体，是节点下的一个子类（如「教育玩具」之于 `2405 玩具`）
  → **禁止作同义词**，必须新增为更细的节点以细化颗粒度：
  节点是 1~3 级 → 该词作为其直接子节点新增（触发**输出条数规则**）；节点是 4 级 → 按下述兄弟挂靠新增。
- **同层并列** —— 该词的语义父级 = 该节点的父级 → 作为兄弟新增，parent = 该节点的父级编号。
- **兄弟挂靠（语义父级在库中无独立节点时）** —— 找语义最接近的既有产品（尤其是 4 级叶子），
  把该词作为其同级兄弟新增：parent_code 取该产品编号去掉末 2 位（即其真实父级），由系统分配下一编码。
  典型例：「三折叠手机」之于 `39270103 折叠屏手机`（其 3 级父级 `392701` 下已排到 39270114）→ 新增 `39270115 三折叠手机`。
- **无法确认是最后手段**：禁止因「缺少某个中间层节点」而判无法确认——先按兄弟挂靠处理；
  只有全库确实找不到任何语义相关分支时才允许，且必须列出检索过哪些分支、为何都不合适。

> **零增益同义词禁令**：产品名用于企业经营范围、专利标题等文本的正则匹配。若该词包含目标主名
> （如「教育玩具」⊃「玩具」），凡能匹配该词的文本必然已匹配主名，作同义词对匹配**零增益**，
> 且会把更细颗粒产品吞进粗颗粒——**一律禁止录入**，该词必须走下位细分新增。

### 步骤 4 · 定位父级与行业大类
- 先定**国民经济行业大类**：1 级编码与国标行业大类一一对应（如 C35 ↔ `35`）。
- 再逐级向下定位到 4 级，**不得跨层级归类**。
- 行业大类字段沿用父级：`python scripts/query_kb.py path <候选父级编号>` 核对。

### 步骤 5 · 分配编码
- 新编码 = 父级编码 + 同级顺序号（2 位，取现有同级最大值 + 1）。
- 用 `python scripts/query_kb.py next <父级编号>` 计算，不要手算。
- 同级超过 99 个时报错，不得继续分配。

### 步骤 6 · 冲突与噪声复检
- 唯一性：名称与同义词在全库不得重复；同名不同类必须加正则区分词 `产品名（区分词1-区分词2）`。
- 同义词增益：判定为「作为同义词」时，复核该词**不得包含目标主名**（如「教育玩具」⊃「玩具」为零增益同义词，
  禁止录入，应改为下位细分新增）。
- 噪声：检查是否有更长的产品名包含该词（子串）。
  库内按**最长匹配**处理，短同义词不会被长产品名抢走，**子串包含不构成阻断**，但须在输出中列出来供人工复核。
- 若该词明显过于通用、预期匹配噪声过大（参照手册「企业量过多」），给出加正则区分词或改用更精准名称的建议。

### 步骤 7 · 输出
1. 结论：新增 / 作为 `【产品编号】` 的同义词，并简述依据（1–3 句）。
2. 数据行表格 + TSV。
3. 落表影响提示：【层级】sheet 需同步修改哪些名称、影响多少行。
4. 冲突与噪声提示（若有）。
5. 替换词规则已覆盖的等价写法（无需重复录入同义词）。

### 步骤 8 · 存档确认（必做，输出数据行后立即执行）

输出数据行后，用**宿主提供的选项/确认控件**（如 AskUserQuestion；若宿主无此能力，则在回复中用文字明确询问）向用户给出两个选项，**不要擅自写文件**：

| 选项 | 行为 |
|---|---|
| **存档** | 写入平台 SQLite 知识库 `data/addprod.sqlite`（product 表事务写入，直接更新，不生成备份文件；平台【层级】视图实时推导） |
| **以后再说** | 不写入，直接结束；仅保留本次返回的数据行 |

选择「存档」时的执行顺序：

1. 把结论转成 spec：`同义词挂入` → `synonyms`；`新增` → `add`（按输出条数规则补齐的所有行都要进 add）。
2. **先跑 dry-run**，把写入计划展示给用户确认：
   ```bash
   python scripts/apply_kb.py --syn 3503=工程机械 --dry-run
   python scripts/apply_kb.py --add "35031001|盾构机|4|C35|全断面隧道掘进机" --dry-run
   python scripts/apply_kb.py --spec spec.json --dry-run      # 混合场景用 spec
   ```
   输出示例：`新增 35031001 盾构机 L4 C35`（SQLite 模式；`--kb` 指定 xlsx 时还会显示插入行号）
3. 确认无误后去掉 `--dry-run` 正式写入（直接更新知识库，**不生成任何备份文件**）。
4. 回报：新增/修改行数。写入后平台与技能查询立即同源可见。

选择「以后再说」时：不执行任何写操作，回复中说明「未写入，数据行已保留，需要时随时可存档」。

## 落表要点（写入必须按编号顺序插入，不能追加到末尾）

- 两个 sheet 均按 `int(编号)` 严格升序：【结构化】按 `int(产品编号)`，【层级】按 `int(四级编号)`。
- `scripts/apply_kb.py` 已实现按序插入、复制邻行样式、编号以文本写入（保住前导零）、同步【层级】祖先名称。
- 同义词先于新增执行，保证新增行的祖先名称已包含新同义词。
- 只有 4 级产品才在【层级】落完整路径行；1/2/3 级只在【结构化】新增。
- 父级不存在时脚本会跳过该条并明确提示（不会静默写错位置）。
- **不生成备份文件**：写入直接更新知识库（SQLite 或 xlsx），避免项目体积随存档累积膨胀；如需留存快照，用平台导出功能手动下载。
- **避免并发写入**：脚本无文件锁，两个流程同时落表会互相覆盖；同一时间只跑一次。

## 校验清单（输出前逐项确认）

- 编码为 8 位（4 级）或符合目标层级长度，且与父级前缀一致
- 产品层级数值与编码长度一致（2 位=1 级，4 位=2 级，6 位=3 级，8 位=4 级）
- 行业大类与 1 级编码对应，且与父级一致
- 同义词用中文分号 `；` 分隔，且**不含主名、不含冒号**（【结构化】写法）
- 同义词场景：该词不包含目标主名（零增益同义词禁止录入），且确为上位统称而非下位细分
- 新增场景已按输出条数规则补齐下级产品
- 未把「统一替换词」的等价写法重复写进同义词

## 写入纪律

- 只有用户在步骤 8 **明确选择「存档」**时才写文件；选择「以后再说」或未经确认，一律不写。
- 写入统一由 `scripts/apply_kb.py` 完成（先 dry-run 再写、按序插入），**不要手工改 xlsx**。
- 写入后不生成备份文件；回报时只说明写入的数据源路径与变更行数。
