# 产品分类知识库 · 数据结构与既有惯例

## 1. 文件与 sheet 规格

知识库：`references/产品分类知识库.xlsx`（相对技能根目录；脚本已按此默认解析，可用 `--kb` 覆盖）
维护手册：`references/产品分类知识库维护手册.docx`

| sheet | 规模 | 内容 |
|---|---|---|
| 层级 | 29302 行 × 9 列 | 四级结构的**完整路径展开**，每行是一条 1→4 级链路 |
| 结构化 | 34995 行 × 5 列 | **扁平落表**：所有层级节点各占一行 |

> 上表行数为 **2026-09-10 快照**，写入后会变化。实际值以 `scripts/query_kb.py info` 的实时结果为准。

列结构：

- 【层级】`一级编号 / 一级名称 / 二级编号 / 二级名称 / 三级编号 / 三级名称 / 四级编号 / 四级名称 / 行业大类`
- 【结构化】`产品编号 / 产品名称 / 产品层级 / 产品行业大类 / 产品同义词`

**行数量关系**：结构化行数 = 层级行数（4 级叶子）+ 1/2/3 级节点数（5693）。
即【层级】只收录 4 级叶子链路，【结构化】收录全部层级节点。

## 2. 写法差异（易错点）

- 【层级】的名称列把同义词内联：`建筑工程机械：建筑工程用机械`
- 【结构化】的 `产品同义词` 列**只放同义词、不含主名、不含冒号**：`建筑工程用机械`，多个用 `；` 分隔。
- 两处必须同步。改动【层级】某级名称时，该节点下所有叶子行都要改（如 3503 影响 75 行）。

## 3. 既有惯例（判断新增 vs 同义词的关键依据）

- **行业统称词 / 上位词 → 作为老词同义词，不新增节点。**
  先例：`3515 农业种植机械`（2 级，C35）的同义词含 `种植机械；农业机械；农用机械；农业机具；农机具`。
- **短词被长词包含是库内常态**，说明检索为最长匹配/边界匹配，新增短同义词不会被长产品名"抢走"，也不会误吞长产品名：
  - `农业机械` ⊂ `农业机械服务` / `农业机械作业` / `农业机械设备市场`
  - `农产品` ⊂ `农产品初加工机械` / `农产品干燥机械`
  - `工程机械` ⊂ `工程机械用特厚钢板` / `工程机械运输` / `工程机械行业工业互联网平台`
- 结论：子串包含**不构成阻断**，但需在输出中提示，便于人工复核。

## 4. 典型案例：工程机械

- 全库无精确名「工程机械」，也无「工程设备」「工程装备」（仅 `3711 海洋工程装备`）。
- 语义等价于 2 级节点 `3503 建筑工程机械`（C35），其下 9 个 3 级：
  桩工机械(350301)、混凝土机械(350302)、建筑运输机械(350303)、压实机械(350304)、养路机械(350305)、
  摊铺机械(350306)、筑路机械(350307)、线路铺装机械(350308)、公共工程机械(350309)。
- 因它是 2 级概念的统称，无法挂到任一 3 级下，新增 2/3 级又会与 3503 重复 → **只能作为同义词**。
- 结果行：`3503 | 建筑工程机械 | 2 | C35 | 建筑工程用机械；工程机械`

## 5. 工具链注意事项

- 本地 `editor_sdk` MCP 打开该 xlsx 后，`sheet_get_sheet_info` 可能返回 `No workbook open`，且 `tencent-docs-sheetagent` skill 不存在。
- 按路由规则的兜底条款：**直接用 openpyxl 读取**；docx 用标准库 `zipfile` + `word/document.xml` 解析，无需 python-docx。
- 推荐使用 `scripts/query_kb.py`（`read_only=True`，秒级加载 3.5 万行）。
- 所有路径均为相对技能根目录，脚本用 `__file__` 反推根目录，故从任意工作目录调用均可。
- **该知识库经体检确认不含公式、图片、图表、透视表、表格对象**（18 个包内条目，仅 2 个 worksheet），
  因此 openpyxl 往返保存是安全的。若换成其他知识库，`apply_kb.py` 的写入预检会自动检测并拦截。
