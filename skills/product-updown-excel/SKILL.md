# 产品上下游关系 Excel 生成器

## 一、用途与触发

触发输入格式：**`产品上下游：【产品编号】`**，例如 `产品上下游：3923`。
产出该产品及其全下级（L3 子类 / L4 产品）的上下游关系边表。产品编号取自《产品分类知识库》。

## 二、输入输出契约

### 入参

| 参数           | 必填     | 说明                                                         |
| ------------ | ------ | ---------------------------------------------------------- |
| `product`    | 是      | 产品编号，如 `3923`                                              |
| `--kb`       | 否(有默认) | 《产品分类知识库》路径；默认读随 skill 分发的 `references/`                   |
| `--graph`    | 否(有默认) | 《产业链图谱》路径；默认读随 skill 分发的 `references/`                     |
| `--edges`    | 否      | **大模型给出的边数据**，直接传 JSON 字符串即可，不要为此建文件（见下方）                  |
| `--kbmap`    | 否      | 图谱节点名→KB码，**直接传 JSON 字符串即可，不要为此建文件**；不提供则仅产出"完全同名"精确匹配到的部分 |
| `--gongyi`   | 否      | 仅用于**复用已有的**工艺常识 Excel（12 列表）；没有历史文件就不要用                   |
| `--head-ent` | 否      | 头部企业名称，驱动税票商品/上市信息穿透                                       |
| `--graph-rt` | 否      | 产业图谱来源的**默认关系类型**（默认 `物料投入`）；设备类链条可设 `装备支撑`                |
| `--no-chanye`| 否      | 关闭脚本内置的图谱采集，改由大模型解析《产业链图谱》后经 `--edges` 给出                  |
| `--out`      | 否      | 输出路径；默认写入**当前工作目录** `{产品编号}{产品名称}.xlsx`                    |

### 两条取数路径（必读）

**脚本不会自己去调 MCP。** `IFACE` 出厂就是占位（见第九节），所以「依赖外部接口的来源」默认产出 0 条边——这**与 MCP 是否连通无关**，不要据此判断"接口没连上"。要用这些来源，必须走下面两条路径之一补数：

| 路径   | 做法                                                                                     | 适用                    |
| ---- | -------------------------------------------------------------------------------------- | --------------------- |
| **B（推荐，默认）** | 由你（大模型）用 MCP 工具编码调用对应 API → 把返回的文本/产品做**语义对齐到 KB 编码** → 连同 `rt`/`st`/`src` 经 `--edges` 注入 | 常规单次生成               |
| **A（固化管线）** | 把 `IFACE` 里的 `None` 换成自己的取数函数（返回已对齐 KB 码的结构）                                            | 反复批量跑、已确定对接方式的生产部署场景 |

路径 B 的来源对应关系：

| 来源   | MCP 工具编码                                                                                    | 取数要点                                                                                       |
| ---- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 税票商品 | `enterprise_trade_analysis`(R1401) + `enterprise_industry_chain`(R1521V2)                   | R1401 取交易方（筛 `entChainName` 非空），按 `roleType` 定上下游；再逐个查 R1521V2 的企业产品 → 对齐 KB 码              |
| 上市信息 | `enterprise_listed_info`(R4G04V2)                                                           | 从 `MAINPRODUCTS`/`MAINBUSIN`/`COMPPROFILE` 三段文本解析上下游 → 对齐 KB 码                              |
| 舆情资讯 | `enterprise_sentiment`(R331)                                                               | 以产品名为 keyword 检索，分析文章标题与正文得出上下游 → 对齐 KB 码                                                  |

脚本结束时若这些来源为 0 条，会打印「**取数缺口**」清单（含对应 MCP 工具编码）——看到它就按路径 B 补数后重跑，**不要当成运行失败**，也不要直接产出只有「工艺常识」的结果就交付。

### `--edges` 边数据 json 格式

由大模型完成语义对齐后**直接**给出的边，数组形式，**作为 `--edges` 的参数值传入**：

```bash
--edges '[{"up":"2625","dn":"3923","rt":"物料投入","st":"强","src":"工艺常识"},
          {"up":"3923","dn":"3601","rt":"物料投入","st":"中","src":"舆情资讯"}]'
```

字段：`up` 上游KB码、`dn` 下游KB码、`rt` 关系类型、`st` 关系强度、`src` 来源名（须已在 `SRC_CONF` 登记）、`conf` 置信度（可省略，按来源默认）。
工艺常识、舆情资讯等**由大模型得出的边一律走此通道**，不另建中间文件。

### 输出

- 文件名：`{产品编号}{产品名称}.xlsx`（如 `3923传感器.xlsx`）。
- **全流程只产出这一个文件**；大模型给出的边经 `--edges` 直接注入，不产生任何中间文件。
- **仅 1 个 sheet**，名为 `Sheet1`。
- **12 列**：关系ID / 上游编号 / 上游名称 / 上游层级 / 下游编号 / 下游名称 / 下游层级 / 关系类型 / 关系强度 / 建边层级 / 依据来源 / 置信度。
- **字号与结构对齐模板**：微软雅黑 10pt，表头加粗，数据行常规；不设列宽/冻结/合并（与模板一致）。

### 输出排序规则（三段）

| 序   | 分组                       | 组内排序            |
| --- | ------------------------ | --------------- |
| 1   | **入参产品系列作为下游**           | 下游编号升序 → 上游编号升序 |
| 2   | **入参产品系列作为上游**           | 上游编号升序 → 下游编号升序 |
| 3   | **非入参产品系列相关**（来源顺带挖出的关系） | 上游编号升序 → 下游编号升序 |

判定：下游编号属于入参系列 → 组1；否则上游编号属于入参系列 → 组2；两端都不属于 → 组3。
组3 是加工中由上市信息等来源**顺带挖出**的关系（与入参系列无关），保留并排在最后；脚本会打印三组条数便于核对。

### 未配置即无数据的原则（重要）

脚本**不含任何产品系列的内置数据**。文件未提供、接口未接入或调用失败，对应来源一律产出 **0 条边**，不回退到任何默认/示例数据。加工 A 产品时绝不会带出 B 产品的边。

## 三、12 列的取值规则

| 列       | 规则                                                                |
| ------- | ----------------------------------------------------------------- |
| 关系ID    | `R` + 上游编号补零至 8 位 + 下游编号补零至 8 位。`2625→3923` = `R2625000039230000` |
| 上游/下游编号 | KB 产品编码（字符串）                                                      |
| 上游/下游名称 | 由 KB `层级` 表查得                                                     |
| 上游/下游层级 | KB 中的层级：L1/L2/L3/L4                                               |
| 关系类型    | 见下表《关系类型》                                                         |
| 关系强度    | `强`/`中`/`弱`，由各来源的信号强度给出；合并时取最强                                    |
| 建边层级    | `min(上游层级, 下游层级)`                                                 |
| 依据来源    | 单个来源，或逗号拼接的多值（按置信降序）                                              |
| 置信度     | 由来源决定，见下表；合并时取最高档                                                 |

### 关系类型

| 关系类型 | 含义                           | 生成规则                   |
| ---- | ---------------------------- | ---------------------- |
| 物料投入 | 上游构成下游的实体组成部分（被消耗或转化）        | 上游→下游 单条               |
| 装备支撑 | 上游是生产下游所用的装备、产线或生产设施，不构成下游实体 | 上游→下游 单条               |
| 服务支撑 | 上游是为下游提供的检测、认证、运维、设计等服务      | 上游→下游 单条               |
| 联产副产 | 上下游在同一工艺中联产                  | **上游=主产品，下游=副产品**      |
| 相互替代 | 两者可互相替代，属横向关系而非上下游           | **每个关系落两条边：A→B 与 B→A** |

脚本对 `相互替代` 自动补全反向边（保持同来源/同类型/同强度），来源只给一条时也会成对输出。

**判定指引（别一律按物料投入）**：分界在于"上游是否被消耗或转化为下游实体"——

| 情形                       | 关系类型  |
| ------------------------ | ----- |
| 上游被消耗/转化，构成下游实体组成部分      | 物料投入  |
| 上游是生产下游所用的设备、产线、生产设施     | 装备支撑  |
| 上游是为下游提供的检测、认证、运维、设计、EDA 等软件与服务 | 服务支撑  |

产业图谱、工艺常识来源尤其容易把光刻/热处理设备、EDA 软件误标成「物料投入」，造成关系类型失真。产出前必须复核脚本打印的**关系类型分布**。

### 依据来源与置信度

| 来源   | 置信度 | 释义                            | API           |
| ---- | --- | ----------------------------- | ------------- |
| 税票商品 | 高   | 企业税票商品申报登记（事实，交易颗粒度）          | R1401→R1521V2 |
| 上市信息 | 中   | 企业公开披露的主营产品（事实）               | R4G04V2       |
| 工艺常识 | 中   | 领域共识知识（大模型）                   | 无             |
| 产业图谱 | 低   | 产业链节点结构；与 KB 码制独立，节点粒度未必贴合产品级 | 《产业链图谱》       |
| 舆情资讯 | 低   | 以产品名称为关键词检索的舆情资讯，经新闻内容分析得出    | R331          |

- 来源可扩展：新增来源时在脚本 `SRC_CONF` / `SRC_ORDER` 登记并补对应采集函数即可。
- 各来源给出的产品名/描述/税码**不含 KB 产品编码**，需由大模型语义对齐到 KB 编码后入库。
- 置信度只反映来源本身的事实可靠性，不反映对齐质量。

## 四、加工流程

1. **加载 KB**：读《产品分类知识库》`层级` 表，构建 `code2name` / `code2level` / `parent`。
2. **确定产品子树**：KB 编码为定宽零补齐（L1=2 位、L2=4 位、L3=6 位、L4=8 位，如 `01`/`0101`/`010101`/`01010101`），故「以输入编号为前缀」的所有编码即构成该产品完整子树（输入是 L1/L2/L3/L4 均可）。判定用 `startswith(输入编号)`；前提是所有编码必须经 `zfill(2×层级)` 还原前导零，绝不能 `str(int(code))` 裸用（否则 `0101` 变 `101`，层级宽度丢失、前缀匹配失效）。
3. **采集各来源边**：见第五节。
4. **语义对齐 KB 码**：把来源给出的产品名/描述/税码对齐到 KB 产品编码。
5. **双向关系展开**：`相互替代` 补全为 A→B、B→A 两条边。
6. **合并**：唯一键 `(上游编号, 下游编号)`。
   - 依据来源多值以 **`,`** 拼接，按置信降序排列（同置信按来源固定序，保证可复现）；
   - 置信度取最高档（高>中>低）；
   - 关系强度取最强（强>中>弱）；
   - 关系类型取"最高置信来源"的类型，并列时按 物料投入>装备支撑>服务支撑>联产副产>相互替代；
   - 建边层级取 `min(上游层级, 下游层级)`。
7. **剔除冗余继承边**（见第六节）。
8. **排序 + 校验 + 输出**：按"输出排序规则（三段）"排序后写出（见第二节）。

## 五、各来源的取数路径

1. **税票商品**：头部企业 → **R1401** 取供应链交易对手方（筛 `tradeCloseness`=一级/二级、`entChainName` 非空）→ 对清单内企业调 **R1521V2** 取企业主营产品 → 按 `roleType` 交易角色定向（`1`=上游 → 该企业产品作上游；`2`=下游 → 该企业产品作下游）→ 语义对齐 KB 码。
2. **上市信息**：头部企业 → **R4G04V2** 取三个字段（`MAINPRODUCTS` 主要产品 / `MAINBUSIN` 主营业务 / `COMPPROFILE` 公司简介）→ 由大模型从三段文本中解析上游（采购/成本构成）与下游（应用领域）→ 语义对齐 KB 码。**不再解析年报 PDF**。KB 中无对应编码的产品（如某些工序/服务）不入库。
3. **工艺常识**：由大模型按领域共识直接给出边，经 `--edges` 注入；无需也不应另建中间 Excel。（确有历史沉淀文件时才用 `--gongyi` 复用。）
4. **舆情资讯**：**R331** 以产品名称为 keyword 全文检索舆情资讯（返回文章标题与正文），由大模型分析新闻内容得出上下游 → 语义对齐 KB 码。
5. **产业图谱**：读《产业链图谱》，按"产业链名称"匹配产品名定位链；只取**叶子节点**，`节点所属环节`=1 取上游、=3 取下游；节点名→KB 码由大模型语义对齐后经 `--kbmap` 传入（脚本仅对完全同名者做精确兜底），并排除映射到产品自身/子树的节点。详见第十二节。
   - **关系类型不可一律按物料投入**：全局默认由 `--graph-rt` 指定，也可在 `--kbmap` 中**逐节点**指定 `rt`。设备/产线类节点要给 `装备支撑`，EDA/检测/设计类要给 `服务支撑`。若嫌脚本判定不准，用 `--no-chanye` 关掉内置采集，改由大模型解析图谱后经 `--edges` 给出完整边。

## 六、继承：不冗余存储 + 强度逐级递减

- 某产品的完整上下游 = 自身边 ∪ 父级边 ∪ 祖父边（并集），查询时现算。
- **总表只存自有边**：即"有父级不存子级"。
- **关系强度随继承逐级递减**：祖父级（原始存边）=强 → 父级（向下 1 跳）=中 → 子级（向下 2 跳）=弱 → **孙级（≥3 跳）不继承**。
- **剔除判定条件**：下游节点存在祖先已存"同上游边"时，还**必须校验继承后强度有效**（`weaken(祖先边强度, 跳数)` 非 None）。若祖先距离过远（孙级）导致继承不到，该边**不能**视为冗余而删除，否则会多删边。

## 七、易错点清单

1. **KB `层级` 表同一编码在多行重复**（因下级逐级展开），必须先去重再统计，否则节点数虚高。
2. **KB 编码是定宽零补齐**：L1=2 位、L2=4 位、L3=6 位、L4=8 位（如 `01`/`0101`/`010101`/`01010101`）。`load_kb` 必须 `str(int(code)).zfill(2×层级)` 还原前导零；绝不裸用 `str(int(code))`，否则 `0101` 会变成 `101`，导致输出编码、关系 ID 错误，且子树前缀匹配失效。
3. **剔除继承边必须校验强度有效性**（见第六节），否则多删。
4. **建边层级取 min**，不是上游层级。
5. **悬空端点必须为 0**：所有上下游编号都必须能在 KB 中查到。
6. **税票商品定向依赖 R1401 的 `roleType`**（1=上游、2=下游）：缺 `roleType` 的交易方无法判断方向，脚本跳过并打印计数，不得臆断方向后补边。
7. **KB 与产业链图谱是两套独立编码体系**；用图谱分析上下游需跨系统对齐节点名与 KB 码。
8. **不做子树过滤**：与入参系列无关的"顺带挖出"关系要保留，归入排序第 3 组，不要丢弃。
9. **相互替代必须成对落边**；联产副产方向固定为主产品→副产品，不可倒置。
10. **"接口来源 0 条"≠ 接口/MCP 出故障**：`IFACE` 出厂为 `None` 是未接线的占位设计，脚本不负责调 MCP。要用到这些来源必须走第二节《两条取数路径》的**路径 B**（由大模型调 MCP 取数并对齐后经 `--edges` 注入）。忽略这点会导致产出只含工艺常识一个来源。
11. **关系类型不能一律按物料投入**：设备/产线→装备支撑，检测/认证/设计/EDA 等软件服务→服务支撑。产业图谱来源尤其容易失真；脚本会打印关系类型分布，产出前必须复核。

## 八、输出校验清单

运行后核对：

- 悬空端点 = 0；
- 依据来源覆盖中，各来源按实际可用情况出现；出现「取数缺口」时应补数后重跑，**不要只用工艺常识就交付**；
- 置信度分布与来源构成自洽（有税票商品边则必有"高"）；
- **关系类型分布不应清一色「物料投入」**：设备/产线应为装备支撑、软件与检测服务应为服务支撑。脚本会打印分布便于自查；
- `相互替代` 类型的边成对出现；
- 行数 = 合并后唯一边数 − 剔除的冗余继承边数（脚本会打印，便于复核）。

## 九、接口接入点（代码位置）

脚本 `scripts/generate_updown.py` 顶部 `IFACE` 字典为接口占位：

```python
IFACE = {
    "R1401":   None,  # 供应链交易数据统计
    "R1521V2": None,  # 企业主营产品（事实来源，用于上下游企业产品）
    "R4G04V2": None,  # 上市公司基本信息
    "R331":    None,  # 舆情全文检索内部接口
}
```

接入时把 `None` 换成可调用函数即可；保持 `None` 或调用抛错，均视为该来源无数据（`call_iface` 已兜底返回 None）。

> **这是「未接线」的占位设计，不是 MCP 连不上。** 脚本本身不负责调用 MCP，出厂跑出来这 3 个来源就是 0 条。常规使用请走第二节《两条取数路径》的**路径 B**：由大模型调 MCP 取数并对齐 KB 码后经 `--edges` 注入。

### API 对接表

| API              | 请求参数                                      | 输出参数                                                                      | 限制条件                                                                  | 工具编码                        |

## 十、随 skill 分发的数据文件

product-updown-excel/
├── SKILL.md
├── scripts/generate_updown.py

脚本按**自身文件位置**解析 skill 根目录来定位 `references/`，因此整个目录拷贝到任意机器、任意路径均可直接运行，无需指定绝对路径；也可用 `--kb` / `--graph` 覆盖。打包分享时 `references/` 必须一并带走。

## 十一、运行方式

```bash
# 最小运行（仅用随 skill 分发的数据；依赖接口的来源=0 条，会打印「取数缺口」及其 MCP 工具）
python scripts/generate_updown.py 3923

# 推荐运行（路径 B：由大模型调 MCP 取数并对齐 KB 码后，连同正确的关系类型一起注入）
python scripts/generate_updown.py 3923 \
  --edges '[{"up":"2625","dn":"3923","rt":"物料投入","st":"强","src":"工艺常识"},
            {"up":"35420201","dn":"3923","rt":"装备支撑","st":"中","src":"产业图谱"},
            {"up":"39010100","dn":"3923","rt":"服务支撑","st":"弱","src":"舆情资讯"}]' \
  --no-chanye

# 使用脚本内置图谱解析（--kbmap 可逐节点指定关系类型）
python scripts/generate_updown.py 3923 \
  --kbmap '{"半导体材料":"262505","光刻设备":{"kb":"35420201","rt":"装备支撑"}}'

# 已把取数函数接进 IFACE 后的做法（路径 A：仍建议边数据走内联 JSON，不落中间文件）
python scripts/generate_updown.py 3923 \
  --edges '[{"up":"2625","dn":"3923","rt":"物料投入","st":"强","src":"工艺常识"}]' \
  --head-ent "某某股份有限公司" \
  --out    "输出路径.xlsx"
```

输出默认写入**当前工作目录**的 `{产品编号}{产品名称}.xlsx`。

## 十二、产业图谱的对齐说明

**推荐做法**：由大模型读《产业链图谱》并完成节点名→KB 码的语义对齐后，把得到的**边直接经 `--edges` 给出**（`src` 填 `产业图谱`）。这样**不需要任何映射文件**。

若要使用脚本自带的图谱解析，才用到 `--kbmap`：

- **直接把 JSON 作为 `--kbmap` 的参数值传入**，不要单独建映射文件。**值可以是字符串（套用 `--graph-rt` 默认关系类型），也可以是对象（逐节点指定关系类型）**：

  ```bash
  # 纯字符串：这些节点统一用 --graph-rt 指定的默认关系类型
  --kbmap '{"半导体材料":"262505","陶瓷材料":"26280301","汽车领域":"3601"}'

  # 对象形式：逐节点指定 KB 码与关系类型（设备/软件务必改类型，否则会失真为物料投入）
  --kbmap '{"半导体材料":"262505","光刻设备":{"kb":"35420201","rt":"装备支撑"},"EDA软件":{"kb":"39010100","rt":"服务支撑"}}'
  ```

- 脚本只做**完全同名**的精确匹配作为兜底；不做子串模糊匹配，模糊对齐由大模型完成。

- 未登记的 `rt` 值会回退为 `--graph-rt` 的默认值，不会往表里写脏值。

- 只取链中的**叶子节点**（排除"原材料""零部件""应用领域"等目录节点）；并排除映射到**产品自身或其子树**的节点。

- 若一条链里混有多种关系类型、判定复杂，建议直接加 `--no-chanye` 关掉内置采集，**由大模型解析图谱后经 `--edges` 一次性给出全部边**（含正确的 `rt`）。

> 全流程只产出最终 Excel。除 `--out` 指定的结果文件外，**不要生成任何中间文件**（边数据、映射均直接传参）。
